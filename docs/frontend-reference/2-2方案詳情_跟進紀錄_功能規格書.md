# 方案詳情－跟進紀錄：功能規格書

版本：2026/10/18。

## 1. 目的與範圍

查閱目前單筆購課方案的歷次跟進紀錄，並沿用方案詳情的新增跟進及辦理續約入口。本頁提供歷史查詢及逐筆編輯入口，供修正誤填；不提供刪除、下次追蹤欄位或自動提醒。共用會員摘要與堂數規則沿用已定案方案概況規格。

## 2. 頁面識別與權限

- 建議路由 `/renewal/:memberCourseId?tab=followups`，直接開啟或重新整理均依網址查詢。
- 後端驗證目前方案存在且屬於登入教練；不僅依前端傳入會員或教練 ID 判斷。
- 以 followup.membercourseid 等於目前 memberCourseId 查詢，不跨同會員其他方案，不因同課程跨方案加總。
- 同會員、同課程、同教練跨方案計算最近上課的規則，不適用跟進紀錄範圍。
- 正常、已用完、已完成續約方案均可查看；停用會員保留權限內歷史查詢，不刪除歷史。

## 3. 紀錄欄位

| 顯示 | 資料與規則 |
| --- | --- |
| 本次聯繫時間 | followup.createdate；有效值顯示台灣日期與時分 |
| 聯絡方式 | contactmethod，依新增跟進的正式代碼映射中文；電話、訊息、當面、其他 |
| 跟進結果 | status，依新增跟進的正式代碼映射尚未取得回應、考慮中、同意續約、無意願 |
| 紀錄教練 | followup.coachid 關聯教練姓名；不把登入者姓名硬套到所有歷史紀錄 |
| 聯繫內容 | note，保留文字與換行，空白或 null 顯示 — |

聯繫內容新增規則為選填、最多 500 個 UTF-16 單位、空白存 null；資料庫 nvarchar(max) 可支援。既有較長歷史內容完整呈現，不在查閱時截斷或改寫。未知歷史方式／結果顯示「未設定」或「未知狀態」，不能誤標為未聯繫；缺漏教練姓名顯示 —。

## 4. 時間、排序及最新結果

- createdate DATETIME 代表使用者填寫的本次聯繫時間，不代表系統實際建立時間。
- 新增表單可選日期及時分，預設台灣現在，允許補登，不可晚於現在；新資料秒數固定 00。編輯時可修正聯繫時間；未修改時間則保留既有完整值，明確修改時才將秒數固定 00，不以儲存當下時間覆蓋。
- 排序固定 `createdate DESC, followupid DESC`，比較完整日期時間；同分鐘的新資料以較大 ID 排前。既有帶秒數資料依原完整時間排序，不截成日期或分鐘再排序。
- 既有 createdate 為 NULL 時排在所有有效時間後，多筆 NULL 依 ID 降冪，顯示「聯繫時間未記錄」。
- 畫面顯示至分鐘不代表資料排序忽略既有秒數。
- 工作台、概況若呈現最新跟進結果，必須共用相同排序；最新結果取整筆歷史的第一筆，不取目前分頁第一筆。
- 無任何紀錄才顯示未聯繫；未聯繫不是可新增的跟進結果。
- 今天 15:00 補登今天 09:00 的紀錄，不會蓋過已存在今天 13:00 的結果。
- 同意續約僅代表意願，不建立 MemberCourse 或 Renewal。完成續約也不改寫歷史結果。

## 5. 分頁與查詢

- 本頁不額外加入姓名、分類或結果篩選；只查目前方案。
- 每頁 10 筆，總筆數為目前方案全部紀錄數，固定排序後再分頁。
- 初次進入第 1 頁；切換方案回第 1 頁。分頁資料與總筆數使用同一方案及權限條件。
- 同方案切換其他分頁再返回可保留跟進頁碼；重新整理未保存頁碼時回第 1 頁。建議用 followupPage 保存頁碼，具體路由為前端實作選擇。
- 更新後頁碼超出範圍回最後有效頁，無資料回第 1 頁。

## 6. 入口、返回與更新

- 頁首只保留單一新增跟進入口，前往目前方案的獨立新增頁，不重新選會員。
- 成功新增後回本分頁第 1 頁並重新查詢。補登舊時間可能位於後續頁，不保證新增紀錄固定在最上方。
- 新增失敗不新增歷史；成功後依最新實際聯繫時間重新判定工作台狀態。
- 辦理續約入口沿用已定案規則；停用會員停用按鈕並說明原因，後端仍須拒絕。已有續約紀錄不單獨造成按鈕停用。
- 返回工作台恢復原 scope、已提交姓名、追蹤分類、跟進狀態及工作台頁碼，重新查詢；無來源狀態使用工作台預設。
- 成功新增或編輯跟進不改變堂數、出席及續約關聯；因此四張分類卡不會僅因跟進變動而改變。
- 本頁列表不直接編輯，離開列表不需未儲存確認；新增／編輯表單有未儲存變更時須提示是否離開。

## 7. 載入與錯誤

- 初始方案尚未驗證前不顯示其他會員舊資料或開放操作。
- 紀錄載入中顯示骨架；查詢失敗顯示錯誤及重試，不誤顯示尚無紀錄。
- 方案不存在或無權限時隱藏個資及紀錄，保留返回入口。
- 真正 0 筆顯示此方案尚無跟進紀錄。
- 會員停用不刪除購課、預約、出席、跟進及續約歷史；Service／Entity 必須避免停用造成級聯實體刪除。本頁查詢須能讀取已停用會員的授權歷史。

## 8. API 與資料庫需求

- 查詢輸入：目前方案 ID、頁碼及每頁筆數；登入教練身分由後端取得。
- 回傳：紀錄 ID、完整聯繫日期時間、方式、結果、內容、教練 ID／姓名、總筆數及分頁資訊；共用頁首可重用方案詳情查詢。
- 不因 UI 分頁就強制新增 API；若既有詳情無法支援分頁，再於最終 API 規格定義紀錄查詢契約。
- 沿用 followup 欄位與外鍵，不要求新增系統建立時間、下次追蹤日期或資料表。
- 前後端統一以 Asia/Taipei 解讀未帶時區的 DATETIME，不在序列化時誤轉日期時間。
- 唯讀查詢不新增或修改 Followup、MemberCourse、Attendance 或 Renewal。
- 正式方式與結果代碼沿用新增跟進 API 契約，本文件不另造一組英文代碼。

## 9. 驗收重點

- #001 只顯示 #001 紀錄，其他方案即使同會員同課程也不混入。
- 完整時間降冪、同時間 ID 降冪；補登早上不覆蓋下午結果。
- 目前第 2 頁不會改變工作台最新結果；最新判斷查整筆方案歷史。
- 無紀錄顯示未聯繫；有紀錄但結果缺漏不冒充未聯繫。
- 空白內容顯示 —、換行保留、無重複新增按鈕、每筆有編輯入口、無刪除入口。
- 共 3 筆時一頁顯示完整，上一頁及下一頁停用；超過 10 筆可分頁。
- 新增成功返回第 1 頁並更新；補登不保證置頂。
- 同意續約不建立購課，完成續約不改寫跟進結果。
- 停用會員歷史仍可在權限內查看，辦理續約不可使用；不洩漏其他教練方案資料。
- 直接網址、重新整理、返回工作台保留條件及錯誤重試符合規格。

## 10. 編輯跟進紀錄（本次新增）

- 每筆卡片右側提供「編輯」，前往獨立編輯頁，沿用新增表單元件，不在列表直接修改。
- 建議路由 `/renewal/:memberCourseId/followups/:followupId/edit`；標題「編輯跟進紀錄」，主要按鈕「儲存修改」。
- 依網址方案 ID 與紀錄 ID 重新載入，帶入原值；不是新增預設值，不把聯繫時間重設現在或把結果重設尚未取得回應。
- 可修改本次聯繫時間、聯絡方式、跟進結果及聯繫內容。會員、所屬方案、紀錄教練及 followupid 不可修改。
- 聯繫時間必填，允許過去、不可晚於台灣現在；方式與結果必填，沿用新增合法選項，未聯繫不可選；內容選填，最多 500 個 UTF-16 單位、空白存 null。
- 時間未更動時保留原始秒數；若時間為 NULL，須補填有效時間才可儲存。歷史未知方式／結果須選擇合法值；既有超長內容完整帶入且提示縮至 500，不自動截斷。
- 後端在讀取及更新時皆驗證方案屬登入教練，並驗證 Followup 屬於路徑方案；不得只憑 followupid 更新，不允許改掛其他方案或改寫紀錄教練。
- 正常、已用完、已續約方案皆可依權限更正；停用會員不阻擋此項歷史更正，仍禁止辦理續約。
- 以原 followupid 更新原筆，不新增 Followup、不變更筆數；未填欄位不隱含重設其他欄位。
- 儲存中停用操作；失敗保留輸入、顯示原因並允許重試；不存在或無權限不得寫入。
- 成功顯示「跟進紀錄已更新」，返回同方案跟進紀錄第 1 頁，重新排序及取得最新跟進結果；時間更改可能使該筆移至後續頁，不保證置頂。
- 只改舊紀錄內容不會讓它成為最新；修改最新結果或聯繫時間後，工作台須依完整時間及 ID 重新判定狀態。結果不再符合原工作台篩選時，返回查詢後該列可移出。
- 取消不儲存，回來源跟進頁碼；有變更時先確認離開，無來源則回第 1 頁。
- 打錯內容用編輯；實際再次聯繫須新增另一筆，不覆蓋上一回聯繫事件。
- 沿用現有資料庫欄位即可；本版不保存修改前版本及修改時間，不將 createdate 當修改時間。
- API 須提供單筆讀取及更新能力，可建議 `GET /api/renewal/{memberCourseId}/followups/{followupId}` 與 `PUT /api/renewal/{memberCourseId}/followups/{followupId}`；正式路徑與 JSON 於 API 規格統一。單筆資料已由既有能力取得時可重用，不必重複設計。
- 更新僅寫入可修改欄位，不改 MemberCourse、Attendance 或 Renewal；不自動產生同意續約的其他紀錄。

### 編輯驗收補充

- 三筆卡片各有一個編輯按鈕；表單顯示正確原值。
- 修改後 followupid 與紀錄總數不變，會員、方案與教練不變。
- 修改最新結果可同步更新工作台；修改舊紀錄內容不會改變排序。
- 修改聯繫時間會重新排序；未修改時間不遺失既有秒數。
- 越權或紀錄與方案不匹配時拒絕，取消及失敗不更新紀錄。
- 新增與編輯共用欄位驗證，但時間預設、寫入方式及成功文案依模式區分。
