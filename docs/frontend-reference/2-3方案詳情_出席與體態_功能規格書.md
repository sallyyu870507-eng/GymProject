# 方案詳情－出席與體態：功能規格書

版本：2026/10/18。

## 1. 目的與範圍

於方案詳情查閱目前購課方案的出席統計、InBody 摘要、趨勢與量測紀錄。本頁唯讀，不新增扣堂、補堂、出席修改、體態新增或刪除功能；既有出席管理負責寫入及更正。

本文件的最近 6 筆趨勢及每頁 5 筆表格為本版配置規則，並非由資料庫自動決定。

## 2. 頁面與權限

- 建議路由 `/renewal/:memberCourseId?tab=attendance`，直接開啟及重新整理須依網址重新查詢。
- 後端驗證方案存在，且 MemberCourse.coachid 等於登入教練；不能只信任前端會員 ID。
- 所有資料限目前 memberCourseId，不能混入同會員其他方案、課程或教練。
- 方案概況跨同會員同課程同教練的最近上課判斷不改動；本分頁明確以目前方案為範圍，兩者用途不同。
- 正常、已用完、已續約或會員停用仍可依權限查閱歷史；不因續約而清除舊紀錄。

## 3. 出席統計

關聯 Attendance → Booking → MemberCourse，Booking.membercourseid 等於目前方案。實際上課日期／時間取 ClassSchedule，不用出席資料建立日期代替。

| 卡片 | 規則 |
| --- | --- |
| 已出席 | 非取消預約、有效 PRESENT、課程已開始的紀錄數；顯示堂 |
| 請假 | 非取消預約、有效 LEAVE、課程已開始的紀錄數；顯示次 |
| 缺席 | 非取消預約、有效 ABSENT、課程已開始的紀錄數；顯示次 |

- 以 Asia/Taipei 現在判斷課程開始時間，不把未來課程當已發生紀錄。
- 每個 booking 最多一筆 Attendance，統計以 bookingid 去重，不能因 JOIN InBody 重複累計。
- 無 Attendance、PENDING、取消預約不計入三項，不自動建立 Attendance。
- 三卡計算目前有效紀錄，不是曾經修改過的次數；出席更正後下一次查詢同步改變。
- 本頁已出席是有效 PRESENT 紀錄數；方案概況已使用堂數為總堂減剩堂。正常資料應一致，遇到異常不得以前者覆蓋剩堂或掩蓋差異。
- 空集合為 0；查詢失敗不是 0。

## 4. InBody 資料範圍

- InBodyRecords → Attendance → Booking → MemberCourse，僅目前方案。
- 量測會員 ID 必須與目前方案會員一致，Attendance 須有效 PRESENT、預約非取消且課程非未來。
- InBody 的 inbodyrecords.memberid 須等於經 Attendance → Booking → MemberCourse 取得的會員 ID；Attendance 本身沒有 memberid 欄位。兩條關聯的會員一致性須由後端驗證，不能僅以外鍵存在認定一致。
- 僅取至少一個量測數值非 null 的有效紀錄，不因有出席就假定有量測。
- 每筆 Attendance 最多一筆 InBody，沿用 attendanceid UNIQUE；不跨方案合併。
- 本頁不刪除不合規歷史資料；排除無效項並由既有出席／資料修正流程處理。

## 5. 日期、摘要與空值

- 顯示量測日期取 recorddate，不用購買日或 createdate 代替。新寫入資料由出席模組確保量測日期有效且不在未來。
- recorddate 為 NULL 的既有資料，在列表顯示「日期未記錄」，排在有效日期後，不參與日期趨勢及最近有效日期摘要；不自行回填日期。
- 未來量測日期不納入摘要、趨勢、表格及總筆數，視為資料異常，交由既有資料修正流程處理；本頁不修改或刪除該資料。
- 近期摘要取日期最新且至少一個指標有值的有效紀錄；同日依該 Attendance 對應課程開始時間降冪，再依 inbodyid 降冪。
- 摘要三項都來自同一筆，缺值為 null／—，不抓其他天的數值補齊。
- 體重及肌肉量以 kg、體脂率以 % 顯示；畫面可統一一位小數，資料原精度不因顯示而被改寫。
- 同日多筆紀錄不合併或平均；列表分別顯示，圖表 tooltip 補上課程時間以區分。

## 6. 趨勢與表格

- 預設體重，可切換體脂率或肌肉量，不改變表格及出席統計。
- 各指標從有效且該欄非 null 的資料取最近 6 筆，再按日期、課程開始時間、ID 升冪呈現。
- 不將缺值當 0 或虛構插值。單筆呈現點、零筆提示尚無此項量測資料。
- 表格顯示全部符合條件紀錄，日期、課程開始時間及 inbodyid 降冪；NULL 日期最後以 ID 降冪。
- 每頁 5 筆，總筆數按目前方案且通過上述有效性與日期條件的紀錄計算；未來量測日期不納入表格或總筆數。圖表最近 6 筆不受表格頁碼影響。
- 示意共 6 筆時，第 1 頁完整列出最新 5 筆，第 2 頁列出剩餘 1 筆；不得顯示每頁 5 筆卻只呈現 2 筆且無捲動方式。頁面內容超出視窗時允許整頁向下捲動。
- 初次進入第 1 頁；切換方案重設體重及第 1 頁；同方案分頁切換可保留指標與表格頁碼。
- 更新後頁碼超出範圍回最後有效頁，無結果回第 1 頁。

## 7. 操作與同步

- 新增跟進及辦理續約沿用已定案入口，不在本頁重複放按鈕。
- 停用會員可查歷史，辦理續約停用；會員恢復由管理端處理。
- 出席更正／體態更新後下次查詢讀最新值；本頁不承諾即時推播。
- 返回工作台恢復原查看範圍、已提交姓名、分類、跟進狀態及頁碼，重新查詢；無來源則回預設條件。
- 確定會員停用時不得級聯刪除購課、預約、出席、跟進及續約歷史；InBody 歷史亦須保留。

## 8. 載入與錯誤

方案驗證前隱藏舊會員資料。出席與 InBody 可獨立載入，單區失敗顯示該區重試，不捏造 0 或空紀錄。無權限／方案不存在顯示對應提示與返回入口。無 InBody 不影響出席統計；只有部分指標有值時正常呈現其餘 —。

## 9. API 與資料庫需求

- 輸入方案 ID、表格頁碼／每頁筆數；指標可前端切換已取得資料，或由 API 參數取得，不強制每次切換新增接口。
- 回傳三項出席計數、最近量測摘要、各指標最近 6 筆有效趨勢、量測表格與總筆數、台灣日期時間基準。
- 量測需保留紀錄 ID、attendanceid、recorddate、課程時間及可為 null 的三個指標，供穩定排序與 tooltip。
- 沿用既有方案詳情、出席及 InBody 查詢能力；最終路徑及 JSON 於 API 規格統一，不假設每個 UI 區塊都需要新接口。
- 既有 SQL 的 inbodyrecords.attendanceid 非空且 UNIQUE、三個量測數值可空，能支援本頁；不新增表或欄位。
- 權限、會員一致性、有效狀態及時間由後端驗證，外鍵本身不保證全部業務條件。
- 本頁 GET 不寫入、不扣堂、不補堂、不建立量測紀錄。

## 10. 驗收

- #001 的統計與體態不混入 #002；概況跨方案最近上課規則仍維持。
- 18 個有效 PRESENT、2 LEAVE、0 ABSENT 顯示 18 堂、2 次、0 次；取消／PENDING／未來課不計。
- JOIN 不重複計數，更正後回查同步變動。
- 無量測不補 0，部分指標缺漏顯示 —；摘要不混用不同紀錄。
- 切指標僅改圖表，最近 6 筆依指標各自選取，不受表格分頁影響。
- 同日多筆排序穩定，NULL 日期不虛構日期、不參與日期趨勢。
- 停用會員歷史依權限可看；未授權教練不得讀取。
- 載入失敗不同於空資料；直接網址、重新整理與返回狀態正常。
