# 辦理續約－功能規格書

版本：2026/10/18。

## 1. 目的與範圍

教練從一筆原購課方案建立一筆新購課方案及續約關聯，支援同課程續購與不同課程加購。每次提交只購買一門課程；本頁登錄購課與付款資訊，不整合支付平台或執行扣款。不涵蓋管理端首次購課、退款、撤銷、編輯續約及跨教練轉購。

## 2. 頁面與權限

- 建議前端路由 `/renewal/:memberCourseId/renewals/new`，以路徑方案為原方案；API 路徑另行定案。
- 依網址 ID 讀取原方案，重新整理與直接開啟仍可載入，不僅信任上一頁資料。
- 後端驗證原方案存在且 coachid 等於登入教練 ID；提交時重新驗證。
- 會員沿用原方案，不能更換；新方案教練固定為登入教練，不能指定他人。
- 不同課程加購僅限登入教練可授課課程。跨教練購課由管理端購課流程處理，本頁不提供教練切換，也不自行建立跨教練續約關聯。
- 原方案可以尚有剩堂、已用完或已完成續約；不要求最新跟進為同意續約。
- 已存在成功續約不禁止再次從同一原方案辦理；但會員須為啟用狀態，停用時不得辦理。

## 3. 唯讀摘要

顯示會員姓名、原方案編號、原課程、原教練、原購買日與原方案剩餘／總堂數。資料只取目前方案，不跨方案加總，不在本頁修改會員、舊堂數或原購買日。

## 4. 新購課表單

| 欄位 | 必填 | 初始值 | 驗證 |
| --- | --- | --- | --- |
| 課程 | 是 | 原課程（仍可授課時） | 必須為登入教練目前可授課的有效課程 |
| 教練 | 系統指定 | 登入教練 | 唯讀，後端取得身分 |
| 購買堂數 | 是 | 空白 | 大於 0 的整數，符合資料庫 INT 範圍 |
| 本次購課金額 | 是 | 空白 | 0～2,147,483,647 的整數，不接受小數；不得溢位或自動截斷 |
| 付款方式 | 是 | 未選 | 現金 cash、轉帳 transfer、信用卡 card；僅接受這三個小寫代碼 |
| 購買日期 | 是 | 台灣今天 | 可選今天或過去日期，允許補登，不得晚於台灣今天；後端驗證後儲存選定日期 |
| 備註 | 否 | 空白 | 最多 500 個 UTF-16 單位，可換行；trim 後空白或未傳以 null 儲存 |

- 金額允許 0，沿用既有資料庫 amount ≥0 約束；0 仍須手動輸入，不把空白當 0。若團隊另定售價政策，再同步變更。
- 本次購課金額由教練手動填寫「本次全部購買堂數的總金額」，不是單堂價格。course.price 雖存在，本頁不使用它自動計價、乘堂數或覆蓋輸入值。
- 付款方式採下拉選單：現金→cash、轉帳→transfer、信用卡→card。前端顯示中文、API 與資料庫儲存小寫代碼；後端拒絕三項以外的值。NVARCHAR(50) 能儲存這些代碼，不代表必須手打或需要新增資料表。
- 原課程不在目前可授課選項時，不強制選中失效課程；提示改選可授課課程。
- 無可選課程時顯示「目前沒有可辦理的課程」，禁止提交。
- 送出時再次驗證課程與教練配對，不能只依前端下拉過濾。
- 新方案 status 明確寫入 active，與現有 SQL 預設值一致，不由前端指定。扣堂／補堂後依第 12 節已定案的生命週期同步更新。

## 5. 購買日期與續約登錄時間

- 購買日期預設 Asia/Taipei 今天，可修改為過去日期，允許補登，不可選未來日期；前後端均驗證必填、有效日期、不早於原方案購買日且不晚於台灣今天；同日可辦理。
- 前端提交日期值，格式 YYYY-MM-DD；畫面顯示 YYYY/MM/DD。新方案 `MemberCourse.purchasedate` 儲存經驗證的使用者選定日期，不自動覆蓋成提交當日。
- `Renewal.renewaldate` 代表「續約登錄時間」，由後端在成功交易內以 Asia/Taipei 當下日期時間產生，保留時分秒，不由使用者選擇或回填。
- 例如 2026/10/18 14:47 補登 10/17 購課：purchasedate 為 2026-10-17，renewaldate 為 2026-10-18 14:47:00；兩者不同是正常情況。
- 不新增欄位或修改資料型別：purchasedate 沿用 DATE，renewaldate 沿用 DATETIME。
- 表單跨午夜停留時保留已選購買日期，提交以後端台灣今天驗證，成功回傳實際購買日期及續約登錄時間。
- 補登只回填新方案購買日期，不回溯建立當時的系統狀態；續約提醒在本次交易成功後依現有 Renewal 關聯更新。
- 購買日期仍參與既有購買日排序，以及從未出席分組最早購買日的久未到課計算，不以 renewaldate 取代。

## 6. 續約與加購關聯

- 同課程續購、不同課程加購都算本原方案的續約，前提為從本頁成功建立實際 Renewal 關聯。
- 每次提交新增一筆 MemberCourse 與一筆 Renewal；另一門課必須另次進入表單並提交。
- 一筆原方案可有多筆 outgoing Renewal；每筆新方案僅對應其合法來源關聯，不重複使用已有新方案。
- 原、新方案必須屬於同一會員，本頁亦固定同一登入教練；此規則由後端驗證及指定，不以外鍵存在視為已保證。
- 只要存在至少一筆成功 outgoing Renewal，即視為原方案已完成續約。
- 額外購課未建立 Renewal 關聯，不自動視為原方案完成續約。
- 不因課程不同而拒絕續約，也不把「原新方案 ID 不同」誤解成必須不同課程。

## 7. 寫入與交易一致性

| 資料表／欄位 | 寫入規則 |
| --- | --- |
| 新 MemberCourse.membercourseid | 資料庫產生，不沿用原 ID |
| 新 MemberCourse.memberid | 原方案會員 ID |
| 新 MemberCourse.coachid | 登入教練 ID |
| 新 MemberCourse.courseid | 本次選擇課程 ID |
| 新 MemberCourse.purchasedate | 使用者選定並通過驗證的購買日期 |
| 新 MemberCourse.totalsessions | 本次購買堂數 |
| 新 MemberCourse.remainingsessions | 等於本次購買堂數 |
| 新 MemberCourse.status | 後端明確設定 active，與 SQL 預設一致，不讓前端指定 |
| Renewal.renewalid | 資料庫產生 |
| Renewal.membercourseid | 原方案 ID |
| Renewal.newmembercourseid | 本次建立的新方案 ID |
| Renewal.renewaldate | 系統成功交易時的台灣日期時間，代表續約登錄時間 |
| Renewal.addedsessions | 本次購買堂數；不是加回原方案 |
| Renewal.amount | 本次輸入金額 |
| Renewal.paymentmethod | 驗證後付款方式代碼 |
| Renewal.note | 選填備註，空白為 null |

- 新方案與 Renewal 必須在同一資料庫交易內一起成功；任一步驟失敗全部 rollback，不留下孤立新方案。
- 原方案剩堂、總堂數、購買日、出席與 Followup 歷史均保留。
- 不自動產生同意續約的 Followup，也不改寫原本最新跟進結果。
- 例：原方案剩 2／20 堂，再買 20 堂，結果為舊方案仍 2／20、新方案 20／20，不顯示舊方案 22／40。

## 8. 重複提交

- 按下確認續約後立即停用按鈕與表單，顯示辦理中。
- 後端亦須以同次提交識別等機制避免重試或雙擊造成重複購課；具體去重契約在 API 規格定義，不假設目前資料表已有對應欄位。
- 相同提交重試應回應同一處理結果；網路逾時未知成功與否時沿用同一識別，不直接建立另一筆。
- 成功後使用者再次進入並明確提交屬另一筆有效購課，使用新的提交識別。
- 不以原方案只能出現一次、相同課程或相同金額作為禁止條件。
- newmembercourseid 的 UNIQUE 只避免同一新方案被多次關聯，不能防止雙擊建立兩筆不同的新方案，不能取代後端提交去重。

## 9. 成功、返回與同步

- 成功提示「續約已完成」，回原方案概況並重新查詢原方案與全部關聯新方案。
- 原方案停止優先聯繫、堂數將盡、已用完提醒；若仍有剩堂且符合久未到課則保留關懷。
- 新方案獨立判斷堂數及續約狀態，不繼承舊方案 Followup。
- 久未到課仍以同會員＋同課程＋同教練跨方案出席判斷；不同課程加購不代表舊課程最近有出席，新購課也不自動重設未到課天數。
- 原方案多筆關聯新方案需完整呈現，不用單一新方案 ID 覆蓋既有關聯。
- 返回工作台時保留原 scope、已提交姓名、分類、跟進狀態與頁碼，重新取得統計及列表；若原列不符合條件可移除，超出有效頁碼回最後有效頁，無結果第 1 頁。
- 取消與返回不寫入；有來源分頁回原分頁，無來源回概況。有修改未儲存時先確認是否離開。
- 成功後再次進入表單須清空堂數、金額、付款方式及備註，避免意外重送上一筆。

## 10. 載入與錯誤

| 狀態 | 行為 |
| --- | --- |
| 初始載入 | 載入原方案及可授課清單，完成前不可提交 |
| 查詢失敗 | 重試提示，不代入他人或示意資料 |
| 方案不存在／無權限 | 顯示適當訊息、提供返回入口，不洩漏個資 |
| 會員已停用 | 顯示停用提示、禁止提交，保留返回方案詳情入口；後端亦拒絕寫入 |
| 課程失效或配對變更 | 阻止提交並提示重新選課 |
| 欄位錯誤 | 顯示原因，保留輸入，聚焦首個錯誤 |
| 儲存失敗 | 交易回復、保留輸入；未知是否成功時依去重機制確認 |
| 成功 | 回原方案概況並更新資料 |

後端重新檢查身分、方案及課程配對；前端停用不能取代後端驗證。不提供即時推播或跨重新整理草稿保留。

## 11. API 資料需求

- 初始化回傳原方案摘要、登入教練、可選課程、付款方式合法選項、台灣日期基準、會員啟用狀態及操作可用狀態／不可辦理原因。
- 提交包含路徑原方案 ID、所選課程 ID、堂數、金額、付款方式、購買日期、選填備註及提交識別。
- 會員、教練、剩餘堂數、status 與續約登錄時間由後端決定；購買日期接受前端選定值，但須由後端驗證。
- 成功回傳 Renewal ID、原新方案 ID、新課程名稱、購買日期、續約登錄時間、堂數及必要付款資訊。
- 可沿用 `POST /api/renewal/{memberCourseId}/renewals`；最終 JSON 名稱與錯誤碼於 API 規格定義；金額固定非負 INT、付款代碼固定 cash／transfer／card。
- 查詢所需資料可重用既有能力，不因本頁就要求每個區塊新增 API。

## 12. 方案狀態與會員停用規則（已定案）

### 12.1 狀態分工

| 欄位 | 用途 | 狀態 |
| --- | --- | --- |
| useraccount.status | 帳號登入狀態 | active／inactive |
| member.status | 會員啟用狀態 | active／inactive |
| membercourse.status | 單筆購課方案的堂數使用狀態 | active／usedup |

會員停用與方案是否用完分開判斷，不把 membercourse.status 改為 inactive。沒有退款及方案到期功能，不新增退款狀態，也不使用 expired。

### 12.2 方案狀態生命週期

- 新購課方案總堂數為正數、剩堂等於總堂，後端明確寫入 active（使用中）。
- 出席扣堂後剩餘為 0，方案狀態更新為 usedup（已用完）。
- 出席更正補回堂數後剩餘大於 0，方案狀態恢復 active。
- 扣堂／補堂與方案狀態必須在同一交易同步更新；SQL 預設值不會自動處理後續變化。
- 辦理續約不因完成續約而把原方案改為 usedup；原方案依自身剩餘堂數維持 active 或 usedup，完成續約仍以 Renewal 關聯判斷。
- 管理端顯示 active 為「使用中」、usedup 為「已用完」，不得任意改成與剩堂矛盾的值。
- 既有非 active／usedup 資料及其他模組依賴須另檢查與整理，不直接無條件覆寫歷史資料。

### 12.3 停用會員的操作與歷史保留

| 操作 | 停用會員規則 |
| --- | --- |
| 查看既有購課、跟進、出席及續約歷史 | 允許，仍須驗證登入教練的方案權限 |
| 辦理新購課／續約 | 禁止，須先恢復會員 |
| 更正既有出席紀錄 | 保留處理能力，仍須依出席模組驗證權限及更正規則 |

- 停用不得刪除購課、預約、出席、跟進及續約歷史，也不清空剩餘堂數。
- 停用或恢復會員，不連動改寫各筆 membercourse.status；剩餘 8 堂的方案仍保留 active 及 8 堂。
- 本頁初始化須取得會員是否停用及是否可辦理的資訊。停用時顯示「此會員已停用，請先恢復會員後再辦理續約」，不開放表單提交，保留返回方案詳情入口。
- 後端在提交交易時重新檢查 member.status；不是 active 時拒絕新購課／續約，不新增 MemberCourse 或 Renewal。不能僅依前端按鈕停用或初始化結果判斷。
- 若開啟表單時會員啟用、提交前被停用，須拒絕寫入並顯示上述提示，保留返回入口。
- 恢復會員由管理端處理，本頁不提供啟用／停用會員功能。
- 此處定義停用後的購課及歷史政策；帳號停用的 Service 與級聯設定須由帳號／會員模組確保不觸發歷史資料刪除。本文件不代表相關程式已完成修改。

## 13. 驗收

- 有剩堂或已完成續約仍能進入，不要求同意續約跟進結果。
- 下拉僅列登入教練可授課課程，允許不同課程加購，後端拒絕未授課配對。
- 會員與教練不能被前端竄改；直接網址亦驗證權限。
- 每次只建立一門課的新方案，堂數／金額空白不送出，堂數非正整數或金額負數、小數或超過 INT 上限失敗，備註空白可成功。
- 新方案剩堂等於總堂，原方案剩堂不變；MemberCourse 或 Renewal 任一步失敗都不留下另一筆。
- 原方案可連續建立多筆續約，查詢回傳完整關聯。
- 同次提交去重，明確再次購買可成功。
- 異課程續約停止原方案續課提醒，但不取消其久未到課關懷；出席分組仍按課程區分。
- Followup 不被自動修改；新方案無紀錄顯示未聯繫。
- 購買日期預設台灣今天，允許過去日期補登，空白、無效、早於原方案購買日及未來日期不可提交。
- 10/18 補登 10/17 時，purchasedate 存 10/17，renewaldate 保留 10/18 實際登錄時間；成功返回及工作台刷新正確。
- 教練固定為登入者，不同課程僅限本人可授課項目；本頁不能替其他教練建立方案。
- 新方案 status 為 active；付款方式僅接受 cash、transfer、card，畫面顯示對應中文。
- 金額為手工輸入的本次總金額，不依 course.price 自動計算。
- 扣堂至 0 同步更新 usedup；更正補回至大於 0 同步恢復 active；續約不把仍有剩堂的原方案改為 usedup。
- 停用會員仍可在權限內查看歷史及更正既有出席，不可新增購課／續約；直接呼叫 API 亦須拒絕。
- 表單開啟後會員被停用，提交仍須阻擋，且不留下任何新方案或續約紀錄。
- 會員停用／恢復不刪除歷史、不清空剩堂、不連動改寫方案狀態。
