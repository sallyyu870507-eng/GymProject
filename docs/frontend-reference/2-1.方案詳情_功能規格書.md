# 方案詳情－方案概況：功能規格書

版本：2026/10/18。

## 1. 目的與適用範圍

讓教練查看工作台某一筆購課方案的會員資訊、堂數使用、最近上課及追蹤提醒，並前往新增跟進或辦理續約。

本規格涵蓋方案詳情共用頁首及「方案概況」分頁。「跟進紀錄」「出席與體態」僅定義切換入口，其內容與操作另行確認；新增跟進、辦理續約的表單及寫入流程亦另有規格。本文件不是整個續約模組的完整規格。

## 2. 頁面識別與權限

- 建議前端路由 `/renewal/:memberCourseId`；預設分頁為方案概況。
- 每次依網址的 memberCourseId 查詢目前方案，不能只依賴上一頁傳入資料。
- 重新整理或直接開啟網址仍能載入。
- 目前方案的 membercourse.coachid 必須等於登入教練 ID；後端負責檢查。
- 可從 TRACKING 或 ALL_PLANS 進入；不符合待追蹤條件的正常／歷史方案仍可經權限驗證查看。
- 共用導覽列選中「續約與關懷」。方案內教練欄代表方案授課教練，不是額外的登入者區。

## 3. 會員摘要

| 欄位   | 規則                                        |
| ---- | ----------------------------------------- |
| 頭像   | 使用會員現有頭像；無頭像時顯示姓名首字占位                     |
| 姓名   | 目前方案所屬會員姓名                                |
| 性別   | 依會員資料轉為顯示文字；未知顯示 —                        |
| 年齡   | 依生日與台灣時區今天計算足歲，今年生日未到需減一；生日缺漏顯示 —，不顯示 0 歲 |
| 電話   | 會員目前電話；缺漏顯示 —                             |
| 電子信箱 | 會員目前信箱；缺漏顯示 —                             |

- 不顯示一般會員或會員等級。
- 本頁只讀，不提供修改個資。
- 電話／信箱僅要求文字顯示，不額外承諾撥號或寄信功能。

## 4. 目前方案資訊與堂數

| 欄位    | 規則                                          |
| ----- | ------------------------------------------- |
| 頁面標題  | 會員姓名・課程名稱・方案編號                              |
| 課程    | 目前方案對應課程名稱                                  |
| 教練    | 目前方案對應教練姓名                                  |
| 購買日   | 目前方案 purchasedate，顯示 YYYY/MM/DD             |
| 總堂數   | 目前方案 totalsessions                          |
| 剩餘堂數  | 目前方案 remainingsessions                      |
| 已使用堂數 | totalsessions − remainingsessions，由後端回傳一致數值 |

- 堂數不得跨其他購課方案加總。
- 本系統目前僅 PRESENT 扣堂，其餘狀態不扣堂；已使用堂數表達目前淨扣除堂數。
- 出席更正而補回堂數後，已使用堂數應同步減少。
- 例：20 − 2 = 18，顯示總20堂、已使用18堂、剩餘2堂。
- 不能用預約筆數或所有 Attendance 筆數作為已使用堂數。
- 若堂數缺漏、負數或剩餘大於總堂數，視為資料異常；不以 0 或強制截斷掩蓋，顯示資料異常提示並由後端回報。
- 本頁不直接修改堂數、課程或購買日。

## 5. 最近一次上課

- 顯示名稱「最近一次上課」，下方小字「同課程・同教練」。
- 計算範圍為目前會員、目前課程及目前教練的所有購課方案。
- 從有效 PRESENT 出席紀錄取得最後實際上課日期，不能取紀錄建立／修改日期代替。
- 不計請假、缺席、取消或未來上課。
- 經 Booking 關聯到 MemberCourse，再以 memberId＋courseId＋coachId 分組；實際欄位與 JOIN 依最新建表 SQL 確認。
- 同組新方案最近有出席，舊方案概況也顯示同一次最近上課日期。
- 整組沒有有效出席時顯示「尚未出席」，不把購買日當作上課日。
- 日期及未到課天數使用 Asia/Taipei 今天，與工作台同一套規則。
- 本頁不顯示「本方案最後出席日」；若未來要呈現，必須另設清楚欄名，不混用。

## 6. 追蹤分類與續約完成

沿用工作台規則：

| 分類   | 條件                          |
| ---- | --------------------------- |
| 優先聯繫 | 本方案剩1～5堂且尚未完成續約             |
| 堂數將盡 | 本方案剩6～10堂且尚未完成續約            |
| 久未到課 | 本方案有剩堂，同會員同課程同教練跨方案至少14天未出席 |
| 已用完  | 本方案剩0堂且尚未完成續約               |

- 同組從未出席，則由不晚於查詢日的最早購買日起算14天；新購課不重設天數。
- 類別可重疊，提醒必須保留同時符合的續課及關懷資訊。
- 已完成續約須有成功 renewal 關聯原方案與新方案，不能由同意續約的跟進結果推定。
- 已完成續約不清空舊方案剩堂，也不停止其出席及歷史查詢。

## 7. 關懷提醒的顯示

提醒由後端依實際資料提供，前端不以固定示意文案判定業務狀態。

| 情況           | 建議顯示文案                                 |
| ------------ | -------------------------------------- |
| 尚未續約，剩1～5堂   | 剩餘 X 堂，建議主動聯繫，了解續課意願。                  |
| 尚未續約，剩6～10堂  | 剩餘 X 堂，可提前了解續課需求。                      |
| 尚未續約，剩0堂     | 本方案堂數已用完，可聯繫了解續課意願。                    |
| 有剩堂且久未到課     | 同課程已 X 天未出席，建議聯繫了解上課安排。                |
| 同組從未出席且達14天  | 同課程購買已滿 X 天，尚未出席，建議聯繫安排上課。             |
| 已完成續約        | 已完成續約，原方案剩餘 X 堂保留；顯示相關新購課方案編號，多筆時分別列出。 |
| 無任何追蹤條件且尚未續約 | 不顯示警示區，避免正常方案仍被要求續課                    |

- 同時符合低堂數與久未到課時，在同一提示區分行顯示兩項，不互相覆蓋。
- 已續約只顯示完成資訊；若另符合久未到課，額外保留關懷文案，不再提示買課。
- 無意願或尚未取得回應不會自行取消堂數／出席分類；與工作台一致。
- 不因尚未定案的提醒文案新增資料庫欄位。

## 8. 返回與分頁

- 返回工作台時恢復 scope、已提交姓名、追蹤分類、跟進狀態及頁碼，再查詢最新資料。
- 若沒有來源狀態（直接開啟詳情網址），返回工作台預設條件。
- 更新後原頁碼超出範圍，回最後有效頁；無結果回第1頁。
- 分頁依序為方案概況、跟進紀錄、出席與體態。
- 切換分頁保留同一 memberCourseId、共用標題、會員摘要及操作入口。
- 建議以 `?tab=overview`、`?tab=followups`、`?tab=attendance` 保存分頁；未指定或未知值回方案概況。此為前端路由建議，不代表新增 API。
- 另外兩個分頁的資料範圍、欄位、統計與編輯功能須另行確認，不由此頁圖推定。

## 9. 主要操作入口

### 新增跟進

- 前往 `/renewal/:memberCourseId/followups/new` 獨立頁，帶入目前方案身分。
- 不在此頁使用抽屜或彈窗，不重新選會員。
- 無歷史紀錄時工作台狀態為「未聯繫」；新增結果只有「尚未取得回應、考慮中、同意續約、無意願」。
- 電話未接或訊息未回仍應記錄「尚未取得回應」。
- 成功儲存後返回同方案的跟進紀錄分頁並重新取得資料；表單細節另定。

### 辦理續約

- 前往 `/renewal/:memberCourseId/renewals/new` 獨立頁，以目前方案為原方案。
- 可由尚未用完的方案進入，不限0堂，且不要求事先把跟進狀態改成同意續約。
- 本頁按鈕只負責前往表單，點擊不會直接建立購課或扣款。
- 成功後重新取得原、新方案關聯與提醒；寫入交易及表單內容另定。

## 10. 載入與錯誤狀態

| 狀態       | 行為                            |
| -------- | ----------------------------- |
| 載入中      | 顯示骨架或載入提示，兩個操作入口停用，不用示意資料代填   |
| 查詢失敗     | 保留返回入口，顯示載入失敗與重試；不可顯示上一會員的舊資料 |
| 方案不存在    | 顯示找不到此購課方案，提供返回工作台            |
| 無權限      | 顯示無權限提示，不顯示會員個資或方案內容          |
| 個別選填資料缺漏 | 依欄位顯示 — 或姓名首字頭像；不阻擋其餘有效資訊     |

成功返回、重新載入及出席更正後的下一次查詢，都以後端最新資料呈現。本頁無即時推播需求。

## 11. API 資料需求

- 目前方案ID、課程ID與名稱、教練ID與姓名、會員摘要。
- 購買日、總堂數、剩餘堂數、已使用堂數。
- 同課程最後出席日；無紀錄為 null，不用虛構日期。
- 日期基準、未到課天數、從未出席時的購買基準。
- 追蹤分類集合、提醒內容／所需判斷資料。
- 是否完成續約，以及與原方案關聯的新購課方案清單；每筆包含方案 ID 與課程名稱。清單包含透過本原方案辦理的同課程續購及不同課程加購，以實際 Renewal 關聯為準。
- 權限與操作可用狀態由後端驗證。

沿用方案詳情查詢能力設計回傳即可；不因拆成分頁就假設每頁必須有新 API。具體路徑、欄位名稱及資料型別待最新 SQL 與最終 API 規格對照。

## 12. 續約與加購操作範圍

- 已完成續約，不代表禁止再次購課；不因已有續約紀錄而停用「辦理續約」按鈕。
- 已完成續約的原方案，仍停止低堂數及已用完的續課提醒；若有剩堂且符合久未到課條件，仍保留關懷提醒。
- 每次辦理只能選擇一門課程，並填寫該門課程的購買堂數。
- 每次按下「確認續約」並成功提交，新增一筆購課方案。
- 可以另外購買不同課程，但須再次進入辦理頁面，選擇另一門課程並分開提交；不提供單次提交多門課程的功能。
- 同一次提交須防止重複點擊造成重複建立；成功後再次進入表單辦理的新購課，屬於另一筆有效操作。
- 續約包含同課程續購及不同課程加購。從原方案進入「辦理續約」並成功提交時，每次新增一筆 MemberCourse 與一筆 Renewal，連結原方案及新方案。同一原方案可以對應多筆續約紀錄；只要存在至少一筆成功續約紀錄，即視為已完成續約，停止該原方案的低堂數及已用完提醒。

## 13. 驗收重點

- 20堂剩2堂顯示已使用18堂，且不跨方案加總。
- 會員生日今年未到，年齡計算不多一歲。
- 舊方案沒使用但同組新方案最近出席，不顯示久未到課。
- 其他課程或其他教練的出席不影響本組最近上課。
- 已續約舊方案仍可查看且剩堂保留，不提示再次買課。
- 有剩堂且久未到課即使已續約仍顯示關懷。
- 同會員、同課程、同教練的所有方案均無有效出席紀錄時，顯示「尚未出席」
- 返回工作台保留查詢條件；直接開啟詳情也能正常載入。
- 本頁不出現會員等級、重複新增跟進按鈕或未確認的其他分頁內容。
