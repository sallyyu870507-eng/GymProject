# 續約與學員關懷工作台－完整功能規格書


## 1. 文件目的與範圍

定義教練端「續約與學員關懷工作台」的顯示內容、分類規則、搜尋篩選、統計、列表及操作行為，作為前端開發、後端 API 設計與測試依據。

本文件涵蓋工作台，以及進入方案詳情和返回工作台的行為。

方案詳情、新增跟進及辦理續約的完整欄位、驗證與寫入規則，由各自規格另行定義。

## 2. 使用角色與查看權限

- 使用角色為登入中的教練。
- 基本資料範圍為 membercourse.coachid 等於目前登入教練的購課方案。
- 「所有方案」仍受上述權限限制，不代表全館所有會員或所有教練的方案。
- 權限由後端驗證，不只依賴前端隱藏資料。

## 3. 資料單位與計算範圍

工作台以購課方案 memberCourseId 為列表、追蹤及統計單位。

| 項目 | 計算範圍 |
| --- | --- |
| 剩餘堂數、總堂數、購買日 | 目前這筆購課方案 |
| 是否完成續約 | 是否存在以目前方案為原方案的成功續約紀錄 |
| 跟進狀態 | 目前這筆方案最新一筆跟進結果 |
| 同課程最後出席日 | 同會員＋同課程＋同教練，跨購課方案計算 |

同一會員不同購課方案分別列出，不合併為一筆會員資料。

## 4. 查看範圍

| scope | 畫面名稱 | 範圍 |
| --- | --- | --- |
| TRACKING | 全部待追蹤 | 符合任一追蹤分類的方案 |
| ALL_PLANS | 所有方案 | 教練有權查看的所有歷史與現在方案 |

預設使用 TRACKING。

ALL_PLANS 包含正常使用、已用完、已完成續約及尚未完成續約的方案。

## 5. 追蹤分類

| 分類 | 條件 |
| --- | --- |
| 優先聯繫 | 目前方案剩餘 1～5 堂，且尚未完成續約 |
| 堂數將盡 | 目前方案剩餘 6～10 堂，且尚未完成續約 |
| 久未到課 | 目前方案剩餘堂數 >0，且同會員、同課程、同教練至少 14 天未實際出席 |
| 已用完 | 目前方案剩餘 0 堂，且尚未完成續約 |

共同規則：

- 四類獨立判斷，不設定優先順序。
- 優先聯繫與堂數將盡不會同時成立，但兩者都可能與久未到課重疊。
- 已完成續約的方案，只可能因久未到課列入待追蹤。
- 同一方案可有多個標籤，但列表只出現一列。
- TRACKING 為四類方案的聯集，去除重複方案。
- 不符合任何分類的方案，只在 ALL_PLANS 查看。
- ALL_PLANS 套用特定追蹤分類時，仍使用相同分類條件。

「已用完」在本工作台是追蹤分類，並非單純代表所有剩餘 0 堂的歷史方案。

已完成續約且剩餘 0 堂的方案，可用 ALL_PLANS＋追蹤分類全部查看。

## 6. 久未到課的日期規則

### 6.1 分組範圍

依 memberId、courseId、coachId 分組，跨該組所有購課方案查詢實際出席紀錄。

### 6.2 計算方式

- 只採計 PRESENT 的實際上課日期。
- 不採計請假、缺席、取消或未來的上課日期。
- 取不晚於查詢基準日的最後一次有效出席日期。
- 若有出席紀錄，以查詢基準日減去最後出席日期，日期差 ≥14 天即達未到課門檻。
- 若整組從未有有效出席紀錄，以不晚於查詢基準日的最早購買日期起算。
- 查詢基準日預設為台灣時區 Asia/Taipei 的今天，按日期計算，不按滿 336 小時計算。
- 新購課不會重設整組未到課天數。
- 達未到課門檻後，只有目前剩餘堂數 >0 的方案取得「久未到課」標籤。

### 6.3 顯示規則

- 工作台欄名為「同課程最後出席日」。
- 指同會員、同課程、同教練跨方案的最後出席日。
- 整組從未出席時顯示「尚未出席」，不將購買日期顯示成出席日。
- 同組多筆有剩堂方案可能同時取得久未到課標籤。
- 統計仍計方案數，不計去重後會員人數。

## 7. 完成續約的判斷與影響

完成續約須存在成功的 renewal 紀錄：

- renewal.membercourseid 指向原方案。
- renewal.newmembercourseid 指向本次建立的新方案。

規則：

- 同意續約的跟進結果不等於完成續約。
- 另外購課但未建立原、新方案續約關聯，不自動認定原方案已完成續約。
- 完成續約後，原方案移除優先聯繫、堂數將盡及已用完追蹤標籤。
- 原方案仍可能符合久未到課。
- 原方案的剩堂、出席及跟進歷史保留。
- 新方案不繼承舊方案的跟進狀態。
- 新方案的堂數與續約完成情況獨立判斷；久未到課則共用同會員、同課程、同教練的出席基準。
- 列表在原方案下方顯示「已完成續約 → 新方案 #編號」。
- 完成續約不改寫過去的跟進結果。

## 8. 跟進狀態

下拉選項：

全部、未聯繫、尚未取得回應、考慮中、同意續約、無意願。

| 狀態 | 定義 |
| --- | --- |
| 全部 | 不限制跟進狀態，僅為篩選選項 |
| 未聯繫 | 此方案完全沒有跟進紀錄，由系統自動判定，不是可手動新增的跟進結果 |
| 尚未取得回應 | 已嘗試聯絡，例如電話未接或訊息未回；有跟進紀錄，且最新結果為尚未取得回應 |
| 考慮中 | 最新結果為會員尚在考慮 |
| 同意續約 | 最新結果為會員有續約意願，但不表示已完成購課 |
| 無意願 | 最新結果為會員目前沒有續約意願 |

最新紀錄依 createdate 由新到舊判定；時間相同時，以跟進紀錄 ID 較大者為最新。

篩選只比對最新結果，不搜尋過去曾有的結果。

例如：過去考慮中、最新無意願，選考慮中不會查到該方案。


### 聯絡嘗試與新增紀錄的狀態規則

- 「未聯繫」只由此方案不存在跟進紀錄自動判定，不新增空白紀錄，也不允許在新增跟進結果中選它。
- 新增跟進結果只提供：尚未取得回應、考慮中、同意續約、無意願；「全部」也不是可寫入的結果。
- 打電話未接或傳訊息未回，仍應新增一筆跟進紀錄，記錄聯絡方式、聯繫內容及「尚未取得回應」。
- 每次後續聯絡新增一筆紀錄，保留歷史；最新結果供工作台顯示與篩選。
- 範例：原本沒有紀錄顯示未聯繫 → 致電未接並儲存，顯示尚未取得回應 → 後續成功聯絡且仍在考慮，顯示考慮中。
- 以「未聯繫」篩選時，已新增未回應紀錄的方案會離開結果；以「尚未取得回應」篩選即可找到。
- 五種實際顯示狀態與四種追蹤分類獨立判斷，不改變堂數、出席及續約完成規則。

## 9. 統計卡片

四張卡片分別統計符合各分類的購課方案數。

- 每張卡片內依 memberCourseId 去重。
- 不同卡片允許計入同一方案。
- 四卡數量不可直接加總為待追蹤總數。
- 統計使用目前登入教練的權限範圍與相同查詢基準日。
- 不受姓名、分類、跟進狀態、列表頁碼或查看範圍影響。
- 每張卡片顯示分類標題、方案數及簡短判斷說明。

點擊卡片：

1. 查看範圍切換為 TRACKING。
2. 追蹤分類選中該卡片分類。
3. 清空姓名搜尋。
4. 跟進狀態重設為全部。
5. 列表回到第 1 頁並重新查詢。

在相同資料快照下，列表符合條件的總筆數應與該卡片數量一致。

## 10. 姓名搜尋與下拉篩選

### 10.1 姓名搜尋

- 搜尋方案所屬會員的姓名。
- 支援部分比對。
- 忽略搜尋字串前後空白。
- 按 Enter 或搜尋按鈕執行。
- 空白字串代表不限制姓名。
- 搜尋結果仍以購課方案為單位。

### 10.2 下拉篩選

追蹤分類：

全部、優先聯繫、堂數將盡、久未到課、已用完。

跟進狀態：

全部、未聯繫、尚未取得回應、考慮中、同意續約、無意願。

- 預設均為全部。
- 每個下拉選單一次選一項。
- 改變選項後立即查詢。
- 使用已提交的姓名條件共同篩選。

### 10.3 條件組合

最終結果須同時符合：

教練權限＋查看範圍＋姓名＋追蹤分類＋最新跟進狀態。

選定特定追蹤分類後，TRACKING 與 ALL_PLANS 結果相同。

只有分類為全部時，ALL_PLANS 才可能額外顯示不需要追蹤的方案。

## 11. 列表欄位

| 欄位 | 顯示內容 |
| --- | --- |
| 會員 | 會員姓名 |
| 課程／方案編號 | 課程名稱、方案編號；已續約時補充新方案編號 |
| 購買日 | 目前方案購買日期 |
| 剩餘／總堂數 | 例如 3／20 |
| 同課程最後出席日 | 同會員、同課程、同教練跨方案的最後 PRESENT 日期 |
| 追蹤分類 | 零個至多個分類標籤 |
| 跟進狀態 | 最新跟進結果；無紀錄顯示未聯繫 |
| 操作 | 查看詳情按鈕 |
- 日期格式為 YYYY/MM/DD。
- 無追蹤分類顯示「—」。
- 無同課程出席紀錄顯示「尚未出席」。
- 同一方案只顯示一列。
- 預設不提供額外的已完成續約下拉篩選；完成資訊以列表文字呈現。

## 12. 排序與分頁

- 購買日期由新到舊。
- 購買日期相同時，memberCourseId 由大到小。
- 每頁 10 筆。
- 顯示符合條件的總筆數、目前頁碼、上一頁及下一頁。
- 修改已提交的姓名、分類、跟進狀態或查看範圍後，回到第 1 頁。
- 統計與總筆數不可只計算目前頁面的資料。
- 更新資料後若目前頁碼超出有效範圍，回到最後一個有效頁；無結果時回第 1 頁。

## 13. 預設、切換與清除行為

首次進入：

- 查看範圍為 TRACKING。
- 姓名為空白。
- 分類與跟進狀態為全部。
- 頁碼為第 1 頁。

切換查看範圍：

- 保留已提交的姓名搜尋條件。
- 分類與跟進狀態重設為全部。
- 回到第 1 頁。

清除篩選：

- 清空姓名輸入與已提交搜尋條件。
- 分類與跟進狀態重設為全部。
- 保留目前查看範圍。
- 回到第 1 頁並查詢。

## 14. 查看詳情與返回

- 點擊查看詳情，依該列 memberCourseId 前往方案詳情。
- 進入詳情前保留查看範圍、姓名、分類、跟進狀態及頁碼。
- 返回工作台時恢復上述狀態，並查詢最新資料。
- 不以會員 ID 取代方案 ID，避免同一會員多筆購課混淆。

## 15. 更新後的資料同步

新增跟進成功：

- 重新取得最新列表。
- 保留目前查看範圍、搜尋及篩選。
- 若最新狀態不再符合篩選，該列從目前結果移除。

辦理續約成功：

- 重新取得統計卡片與列表。
- 原方案停止續課提醒，但仍依跨方案出席規則判斷久未到課。
- 新方案獨立判斷堂數分類與跟進狀態。

出席或堂數變更：

- 工作台下次載入、返回或重新查詢時，重新計算統計與列表。
- 同組任一方案的 PRESENT 紀錄變動，可能影響其他同組方案的久未到課分類。
- 本頁不要求即時推播。

## 16. 載入、空資料與錯誤狀態

| 狀態 | 呈現方式 |
| --- | --- |
| 查詢中 | 顯示載入提示，避免將舊結果誤認為新查詢結果 |
| 教練完全沒有購課方案 | 顯示「目前沒有可查看的購課方案」 |
| 有方案，但沒有待追蹤資料 | 顯示「目前沒有需要追蹤的方案」，提供切換所有方案入口 |
| 搜尋或篩選無結果 | 顯示「沒有符合篩選條件的方案」，提供清除篩選 |
| 查詢失敗 | 顯示「資料載入失敗，請重試」與重試按鈕，保留條件 |
| 無權查看 | 顯示無權限提示，不呈現受限資料 |

統計尚未取得或載入失敗時，不將未知數量顯示成 0。

## 17. 重要情境驗證

| 情境 | 預期結果 |
| --- | --- |
| 尚未續約，剩 3 堂，同課程 20 天未出席 | 優先聯繫＋久未到課；列表一列，兩張卡各計一次 |
| 尚未續約，剩 8 堂，同課程 20 天未出席 | 堂數將盡＋久未到課 |
| 尚未續約，剩 0 堂 | 已用完，不列久未到課 |
| 已完成續約，剩 3 堂，同課程最近有出席 | 不列待追蹤；所有方案可查 |
| 已完成續約，仍有剩堂，同課程 20 天未出席 | 只列久未到課 |
| 舊方案 20 天未使用，新方案同會員、同課程、同教練兩天前有出席 | 兩筆方案都不因舊方案未使用而列久未到課 |
| 會員最近上瑜珈，但重訓課 20 天未出席 | 瑜珈出席不影響重訓課的久未到課判斷 |
| 同組從未出席，最早購買滿 14 天，今天又購買新方案 | 新購課不重設天數；同組有剩堂方案皆可能列久未到課 |
| 致電未接並新增紀錄，最新結果尚未取得回應 | 列表顯示尚未取得回應，可用該狀態篩選；不再屬於未聯繫 |
| 最新紀錄從尚未取得回應更新為考慮中（新增後續紀錄） | 工作台顯示考慮中，原未回應紀錄保留在歷史 |
| 最新跟進為考慮中，尚未完成續約 | 可用考慮中查到，續課分類仍依堂數判斷 |
| 最新跟進為同意續約，但尚未正式辦理 | 不視為完成續約，仍保留符合的續課提醒 |
| 已完成續約，歷史最新跟進仍為考慮中 | 所有方案＋考慮中可查到，並另顯示已完成續約 |
| 新方案沒有跟進紀錄 | 顯示未聯繫，不繼承舊方案結果 |

## 18. API 設計所需資料

本節定義資料需求，實際路徑與 JSON 欄位名稱於 API 規格書定案。

查詢輸入：

- 查看範圍。
- 會員姓名關鍵字。
- 追蹤分類。
- 跟進狀態。
- 頁碼與每頁筆數。
- 教練身分由登入資訊取得。

回傳內容：

- 查詢基準日。
- 四張統計卡數量。
- 符合條件的總筆數及分頁資訊。
- 每筆方案的會員、課程、方案編號、購買日、剩餘與總堂數。
- 同課程最後出席日。
- 可重疊的追蹤分類。
- 最新跟進狀態。
- 是否完成續約及關聯新方案編號。

追蹤分類、出席日期與續約完成情況由後端依本規格統一計算，前端負責呈現與操作。

| 堂數將盡 | 剩餘 6～10 堂，且該方案尚未完成續約 |
| 久未到課 | 尚有剩餘堂數，且同會員、同課程、同教練跨方案最後出席距今 ≥14 天；已完成續約仍可符合 |
| 已用完 | 剩餘 0 堂，且該方案尚未完成續約 |

共同規則：

- 四種分類各自判斷，允許重疊，不設定分類優先順序。
- 同一方案可以顯示多個分類標籤，但列表只出現一列。
- 「全部待追蹤」取四類方案的聯集，同一方案只計一次。
- 四張統計卡各自計數，因此卡片數量不可直接加總。
- 最後一次實際出席日，只取 `PRESENT` 的上課日期，不採用請假、缺席、取消或未來預約日期。
- 久未到課依同會員、同課程、同教練跨方案的最後 PRESENT 上課日期計算；整組從未出席則以該組最早購買日起算，新購課不重設天數；目前方案有剩堂且日期差滿 14 天即符合。
- 兩個查看範圍使用相同的追蹤分類規則。

【三、完成續約的判斷】

「已完成續約」必須有實際成功建立的續約紀錄，連結原方案與新購課方案：

原方案 #001 → 續約紀錄 → 新方案 #002。

- 「同意續約」只表示會員表達意願，不代表已完成續約。
- 另外新增購課方案，若未與原方案建立續約關聯，不自動認定原方案已完成續約。
- 原方案完成續約後，不再因低堂數或堂數用完列入續課提醒。
- 原方案若仍有剩堂且久未到課，仍可列入「久未到課」關懷。
- 原方案剩餘堂數與歷史紀錄保留，仍可繼續使用及查詢。
- 已完成續約的方案，在列表顯示「已完成續約 → 新方案 #編號」，與跟進狀態分開呈現。

| --- | --- | --- | --- | --- |
| 舊方案 #001 | 剩 3 堂、已完成續約、正常出席 | 考慮中，保留原聯繫結果 | 不顯示 | 顯示，並標示「已完成續約 → #002」 |

- 不繼承舊方案的跟進狀態。
- 在「所有方案」中，跟進狀態選「全部」或「未聯繫」即可查到。
- 若另外新增跟進紀錄，結果為「考慮中」，才會符合「考慮中」篩選。
- 依本方案堂數與續約完成情況判斷續課分類；久未到課共用同會員、同課程、同教練跨方案的出席基準。

- 若仍有剩堂且至少 14 天未出席，仍列入「久未到課」。
- 若不符合久未到課條件，則只保留在「所有方案」。

【七、跟進狀態的判斷】

跟進狀態下拉選項：

全部、未聯繫、尚未取得回應、考慮中、同意續約、無意願。

- 「全部」表示不限制跟進狀態。
- 沒有跟進紀錄的方案，顯示為「未聯繫」。
- 有跟進紀錄的方案，以最新一筆跟進結果顯示及篩選。
- 已聯絡但電話未接或訊息未回仍應新增紀錄，結果為「尚未取得回應」；新增結果不提供「未聯繫」。
- 某方案以前是「考慮中」，後來改為「無意願」，選「考慮中」就不會找到；過去紀錄仍可在詳情查看。
- 「跟進狀態」與「是否完成續約」分開判斷。
- 完成續約不改寫過去的跟進紀錄，因此歷史方案可以同時呈現「跟進狀態：考慮中」及「已完成續約 → 新方案 #002」。

【八、操作規則】

- 進入頁面：預設「全部待追蹤」，追蹤分類與跟進狀態都選「全部」。
- 切換查看範圍：保留姓名搜尋，兩個下拉選單重設為「全部」。
- 選擇分類或跟進狀態：立即更新列表，所有條件必須同時符合。
- 「全部待追蹤」的列表標題為「待追蹤方案」。
- 「所有方案」的列表標題為「購課方案列表」。
- 沒有符合結果時，顯示「沒有符合篩選條件的方案」。
- 「清除篩選」清空姓名、將兩個下拉選單重設為「全部」，保留目前查看範圍。
- 四張統計卡顯示教練有權查看範圍內的追蹤數量，不隨姓名、分類、跟進狀態及查看範圍切換變動。
- 成功新增跟進後，重新查詢列表，依最新狀態重新套用篩選；若不再符合條件，該列會從目前結果移除。
- 成功辦理續約或更新出席與剩餘堂數後，重新取得統計卡與列表，依最新資料重新分類。
