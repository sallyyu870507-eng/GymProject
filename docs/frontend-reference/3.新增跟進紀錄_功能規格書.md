# 新增跟進紀錄－功能規格書

版本：2026/10/18。

## 1. 目的與適用範圍

讓登入教練針對一筆購課方案，新增一次聯絡嘗試或聯絡結果，保留歷史，供方案詳情與工作台顯示及篩選。

本規格涵蓋新增表單、權限、驗證、日期時間、儲存、取消及資料同步。不涵蓋編輯／刪除紀錄、續約寫入或自動提醒。版面以「新增跟進紀錄－UI/UX 版面配置規格書」為準。

## 2. 頁面識別與權限

- 前端建議路由 `/renewal/:memberCourseId/followups/new`；路由屬前端設計，不代表 API 已定案。
- 依網址方案 ID 重新查詢，不僅依賴上一頁資料；直接開啟或重新整理仍可使用。
- 後端驗證目前方案存在，且 `membercourse.coachid` 等於登入教練 ID。
- 本頁不可重新選會員、教練或方案。
- 寫入的 `membercourseid` 由目前方案決定；`coachid` 由登入身分取得，不信任前端自行指定的教練身分。
- 正常方案、歷史方案、已用完及已完成續約方案，只要有權查看，均可新增跟進。
- 方案已完成續約或會員無意願，不自動禁止記錄後續關懷。

## 3. 方案摘要

顯示目前方案所屬會員頭像、姓名、課程名稱、方案編號、剩餘與總堂數。全部唯讀，堂數只取本方案，不跨方案加總。

跟進只歸屬目前方案，不同步新增至同會員其他方案。例如重訓 #001 剩堂不足，從 #001 聯絡後的結果只記在 #001；若會員想改購其他課程，可於選填內容說明，實際購課另依續約流程辦理。

無頭像使用姓名首字。方案及權限未確認前，不顯示其他會員的暫存資料，也不可提交。

## 4. 表單欄位與驗證

| 欄位 | 必填 | 初始值 | 規則 |
| --- | --- | --- | --- |
| 本次聯繫時間 | 是 | Asia/Taipei 現在時間，取至分鐘 | 有效日期＋時分，允許補登，不得晚於現在 |
| 聯絡方式 | 是 | 電話 | 電話、訊息、當面、其他，單選 |
| 跟進結果 | 是 | 尚未取得回應 | 四種可新增結果之一，單選 |
| 聯繫內容 | 否 | 空白 | 選填，最多 500 字，可換行；未填或只有空白時以 `null` 儲存 |

- 聯絡方式四項為本文件補充的實作選項；若團隊已有統一代碼，API 設計時統一對映，畫面語意保持一致。
- 聯繫時間初次載入時動態預設台灣現在時間，秒數歸零；使用者修改後不因重新渲染而被重設。
- 本版允許補登過去日期時間，不另限制必須在購買日之後；紀錄仍明確歸屬所選方案。
- 文字框顯示目前長度／500；前後端使用一致的 UTF-16 長度計算方式，避免上限不一致。
- 四種跟進結果的聯繫內容均為選填。未傳、`null`、空字串或去除前後空白後為空時，統一以 `null` 儲存，不阻擋提交；有內容時才驗證最多 500 字。
- 聯繫內容以純文字儲存及顯示，保留內部換行，不當作 HTML 執行。
- 不因本頁限制 500 字而自動修改資料庫 `note NVARCHAR(MAX)`，歷史較長紀錄亦不截斷。

## 5. 跟進結果與工作台狀態

| 狀態 | 意義 | 本頁可選 |
| --- | --- | --- |
| 未聯繫 | 該方案完全沒有跟進紀錄，系統推導 | 否 |
| 尚未取得回應 | 已嘗試聯絡，尚未取得會員回應 | 是 |
| 考慮中 | 會員仍在考慮是否續購 | 是 |
| 同意續約 | 會員表達續購意願，尚不代表完成購課 | 是 |
| 無意願 | 會員目前沒有續購意願 | 是 |
| 全部 | 工作台不限制跟進狀態的查詢選項 | 否 |

- 電話未接、訊息未回仍應新增紀錄，記錄聯絡方式與本次聯繫時間，內容可不填，結果選「尚未取得回應」。
- 「未聯繫」與「全部」不可作為新增結果送出，後端亦須拒絕。
- 工作台沒有紀錄的方案顯示未聯繫，已有紀錄則顯示依排序判定的最新結果；只開啟表單未儲存，不會改變狀態。
- 每次聯絡新增一筆，保留過去紀錄，不覆寫上一筆結果。
- 不將同意續約自動轉為購課，也不自動建立 Renewal。
- 無意願或尚未取得回應不會取消追蹤分類、調整堂數或停止上課權利。

## 6. 本次聯繫時間與 createdate

資料庫結構不修改，沿用 `followup.createdate DATETIME` 儲存使用者填寫的實際聯繫日期時間，精度至分鐘。

- 欄位名稱為「本次聯繫時間」，可選日期、時、分，採 24 小時制，預設 Asia/Taipei 現在時間。
- 可補登過去時間，不得晚於現在；前端提供限制，後端以伺服器的台灣現在時間再次驗證。
- 前端與 API 必須傳遞完整日期＋時分，例如 `2026-10-18T13:57:00`，不得只傳日期；此值約定為 Asia/Taipei 當地時間，不誤當 UTC。
- 後端儲存使用者選定的值，秒數及小數秒統一歸零。例如選 2026/10/18 13:57，儲存 `2026-10-18 13:57:00`。不固定午夜，也不拼接當下提交時間。
- `createdate` 在本模組代表聯繫時間，不另代表資料實際輸入／建立時間；目前沒有獨立建立時間欄位。
- 最新跟進與紀錄列表統一依 `createdate DESC, followupid DESC` 排序，比較完整日期時間，不截成日期；同分鐘的新紀錄以較大 ID 為最新。
- 例如 13:00 記錄考慮中，15:00 補登 09:00 的尚未取得回應，最新狀態仍為 13:00 的考慮中。
- 同分鐘內不記錄實際秒數先後，以 ID 作為排序平手判斷。
- 既有帶時分秒的紀錄保留原值，以完整時間參與排序，不虛構缺少的實際聯繫時間；既有午夜值無法事後還原原本時間。
- 新增紀錄的 createdate 保證非空；既有 NULL 日期時間排在有值資料之後，多筆 NULL 時以 ID 由大到小排列。
- 工作台及跟進紀錄分頁須共用相同排序。紀錄列表顯示 `YYYY/MM/DD HH:mm`，不顯示秒數。

## 7. 下次追蹤安排

- 本頁不設下次追蹤日期欄位，不新增對應資料庫欄位。
- 約定後續聯絡時間時，教練直接寫在聯繫內容，例如「會員考慮中，約定 10/25 再次聯絡」。
- 不解析文字自動產生日期，不提供到期提醒、逾期清單或依下次追蹤日期排序。

## 8. 儲存流程與資料寫入

1. 點擊「儲存跟進紀錄」。
2. 前端驗證必填、日期時間、選項及字數，失敗則顯示欄位錯誤，不提交。
3. 提交期間停用儲存及離開操作，顯示「儲存中…」。
4. 後端再次驗證登入、方案權限及全部輸入。
5. 成功新增一筆 Followup，不修改既有跟進紀錄。
6. 成功回應後，顯示成功提示並返回同方案跟進紀錄分頁，重新查詢資料。

| 現有資料表欄位 | 寫入來源 |
| --- | --- |
| followupid | 資料庫自動產生 |
| membercourseid | 目前方案 ID |
| coachid | 經驗證的登入教練 ID |
| status | 本次跟進結果，由最終 API 統一代碼對映 |
| contactmethod | 本次聯絡方式，由最終 API 統一代碼對映 |
| note | 去除前後空白後的聯繫內容；未填或只有空白時為 `null` |
| createdate | 使用者選定的聯繫日期時間，秒數為 00，依第 6 節處理 |

- 不改動 MemberCourse 堂數、出席、購買日或 Renewal 關聯。
- 同一提交須防止重複點擊與相同請求重試造成重複建立；前端停用按鈕，後端採提交識別碼等去重機制，具體契約於 API 規格定義。
- 不以「內容相同」直接拒絕不同次聯絡；不同次有意新增的相同內容可以是有效紀錄。
- 網路逾時無法確定是否成功時，以同一提交識別重試，不直接當作新的聯絡再送一次。

## 9. 儲存後的同步

- 返回 `/renewal/:memberCourseId?tab=followups`，重新取得同方案跟進紀錄。
- 最新狀態依第 6 節的完整日期時間與 ID 排序計算，不強制以本次新增結果覆蓋工作台。
- 工作台返回時保留原 scope、已提交姓名、追蹤分類、跟進狀態及頁碼，重新查詢最新結果。
- 若新的最新狀態不符合原篩選，該方案離開目前結果；頁碼超出範圍回最後有效頁，無結果回第 1 頁。
- 新增跟進不影響四張追蹤卡片數量；卡片仍由堂數、出席與續約關聯決定。
- 同會員其他方案的跟進結果不受影響，新購課方案不繼承本方案狀態。

## 10. 取消、返回與未儲存內容

- 「取消」與左上「返回方案詳情」都不建立紀錄。
- 有來源分頁時回到原方案原分頁；無來源資訊時回方案概況。
- 使用者已修改任一表單欄位時，取消或站內離開前提示「尚有未儲存的內容，確定離開？」。
- 確認離開則丟棄，繼續編輯則保留內容。
- 儲存失敗保留全部輸入，不自動導離。
- 不提供跨重新整理的草稿保存；瀏覽器關閉或重新整理可使用瀏覽器支援的離開提示，不承諾所有環境都顯示自訂訊息。

## 11. 載入、錯誤與空值

| 狀態 | 行為 |
| --- | --- |
| 初始載入 | 顯示載入提示，資料與權限確認前不可儲存 |
| 載入失敗 | 顯示錯誤與重試，不使用其他方案舊資料代填 |
| 方案不存在 | 顯示找不到此購課方案，提供返回工作台 |
| 未登入／登入失效 | 依共用登入流程處理，不顯示受限個資 |
| 無權限 | 顯示無權限，不允許新增 |
| 欄位驗證失敗 | 顯示欄位原因，保留輸入 |
| 儲存失敗 | 保留內容，提供重試；未知成功與否依去重識別處理 |
| 儲存成功 | 提示成功、返回跟進紀錄並重新查詢 |

提交時仍須重新檢查權限；載入時通過不代表提交時可略過。

## 12. API 資料需求

本節定義契約需求，不將建議路徑或欄位名稱視為已完成的 API。

- 讀取：目前方案 ID、會員姓名及頭像、課程名稱、剩餘／總堂數與操作權限。
- 新增輸入：路徑方案 ID、本次聯繫時間（完整日期時間，秒數 00）、聯絡方式、跟進結果、選填聯繫內容及提交去重識別。
- 教練 ID 由登入資訊取得，不開放使用者選擇。
- 成功回應：新增跟進 ID、所屬方案 ID、本次聯繫時間、結果與必要回傳資料。
- 錯誤回應：可識別的驗證錯誤、未登入、無權限、方案不存在及儲存失敗。
- 沿用新增跟進能力設計；可採 `POST /api/renewal/{memberCourseId}/followups`，最終 JSON 欄位、選項代碼與 HTTP 狀態對照在 API 規格書統一。
- 不因畫面新增名稱而假設資料庫已有 contactDate、nextFollowupDate 或獨立 createdAt 欄位。

## 13. 驗收重點

- 直接開啟頁面可載入正確方案，其他教練不能讀取或新增。
- 無歷史紀錄時為未聯繫；致電未接新增成功後可顯示尚未取得回應。
- 新增結果只有四項，拒絕全部、未聯繫及未知值。
- 聯繫內容未填或只有空白仍可提交，note 儲存為 null；有內容且超過 500 字、晚於現在的聯繫時間或無效選項不可提交。
- 本次聯繫時間預設台灣現在，前後端保留日期與時分，不誤用 UTC 或遺失時間。
- 補登較早聯繫時間不覆蓋較新的狀態；同分鐘新紀錄以較大跟進 ID 判定最新。
- 選 13:57 即存 13:57:00；15:00 補登 09:00 的紀錄不蓋過 13:00 的結果。
- 每次聯絡新增一筆，歷史紀錄保留，不修改堂數、出席或續約狀態。
- 同意續約不自動建立新方案或停止續課提醒。
- 重複點擊／同次請求重試不重複建立；另一個有效提交可以新增紀錄。
- 儲存成功回跟進紀錄分頁；失敗保留輸入；取消不寫入。
- 返回工作台恢復條件並重新查詢，分類卡片不因跟進結果改變。
- 不顯示下次追蹤日期，不提供文字日期自動提醒。
